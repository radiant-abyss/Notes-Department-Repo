# Notes Department Bot — NapCat

## 指令权限隔离

- 未注册用户只能注册，其余指令提示先注册；停用成员不能通过再次注册自行恢复。
- 普通成员仅可使用个人资料、任务认领/提交/进度、任务申请及本人时长查询。
- 普通管理员可使用日常任务及成员管理，但不能操作高级管理者或读取他人时长；综合导出和操作日志排除时长账目。
- 时长负责人属于高级管理员，与总负责人一样可使用全部管理指令；总负责人账号受保护。
- 帮助菜单根据实际权限展示；直接输入未显示指令也会校验，操作过程中撤权同样生效。
- 用 `时长负责人添加 姓名或QQ` 任命高级管理员；普通管理员使用 `管理员添加 姓名或QQ` 任命。

## 志愿时长（月度账本）

自 **2026-10-30** 起登记，按自然月统计。首次区间为 10 月 30～31 日；旧任务中从该日起已审核完成的个人份额进入“待登记”，不会凭空分配小时数。10 月 30 日前完成的任务不自动计入。

- 成果审核：`通过 12 张三 2.5` 同时登记 2.5 小时，归属审核当天。`通过 12 张三` 保留兼容，未有账目的份额列为待登记，不能把漏填视为 0。
- 成员查询：`我的志愿时长` 查本月；`我的志愿时长 2026-11` 查历史月份；`志愿时长明细 2026-11 2` 查看逐笔记录第 2 页。
- 管理查询：`待登记时长 2026-11`；`志愿时长统计 2026-11`（每页 20 人，可追加页码）。
- 补录：`登记志愿时长 12 张三 2.5 2026-10-30`；日期省略时归入今天，跨月补录必须指定归属日期。
- 更正：`更正志愿时长 5 3.0 2026-10-30 工作量核对后调整`，5 是时长记录编号；填写的是新总时长，不是追加值。设为 0 可冲销；原值、原日期、操作人和原因保留。
- 月报：`导出志愿时长 2026-11`，省略月份默认本月。Excel 包含人员汇总、登记明细、更正留痕及统计起止日期，含学号、主修及辅修学院。有效成员无时长也列 0；停用成员在该月有记录时仍列入。当前是按指令导出，没有定时月末自动导出；导出不清零，可重复导出。

总负责人用 `时长负责人添加 张三` 任命有效成员，用 `时长负责人移除 张三` 移除，`时长负责人列表` 查看名单。同名请使用 QQ 号。时长负责人即高级管理员，拥有全部日常管理和志愿时长权限，也可任免时长负责人。普通管理员不能查看他人时长、登记、更正或导出部门时长，不能任免或修改高级管理者。所有注册成员仍可查询自己的时长。

成果提交后固定通知总负责人，同时保留发布人通知并去重；通知失败不撤销成果，会告知提交人。成果审核后、补录或更正时，通知总负责人和有效时长负责人；无论通知是否成功，账目都可查询。QQ 不在线或拒收时无法保证送达。

小时数支持最多两位小数，内部使用整数百分之一小时累计，避免浮点误差。只有明确登记的 0 才表示不计时长。任务重开、重新开放或软删除不自动删除账本，防止历史丢失；高级管理员需明确更正已有账目，再次审核不会重复累计。同一成员同一任务最多一笔当前账目，修改历史独立保留。

这是部门登记账本，不代表已经同步学校志愿平台。配置、凭据、数据库、备份和 exports/ 均保留本机，不要提交 Git。升级新增三张表并先备份数据库，需重启 Bot 才加载新代码；NapCat 无需重启。

本地验证：`python test_volunteer.py`（临时合成数据库，模拟 QQ 消息，不联网）。


## 成员申请部门发布任务

成员私聊发送 `申请任务`，依次填写任务类型、学科、具体内容及所需知识、人数（1～100）、申请理由，发送 `确认` 后进入待审批列表。填写中发送 `取消` 不提交。

申请只是建议部门发布任务。批准前不会进入公开任务列表；批准后创建开放任务，**不自动由申请人认领**，所有符合条件的成员都可按现有规则认领。

| 使用者 | 指令 | 用途 |
| --- | --- | --- |
| 成员 | `我的申请` / `我的申请 2` | 分页查看自己的申请，每页 10 条 |
| 成员或管理员 | `申请详情 12` | 查看完整内容、理由及结果；普通成员只能查看自己的申请 |
| 申请人 | `撤回申请 12` | 撤回尚未审批的申请；修改内容需撤回后重新申请 |
| 负责人或管理员 | `待审批申请` / `待审批申请 2` | 查看待审批申请 |
| 负责人或管理员 | `批准申请 12` | 创建正式公开任务，并通知申请人及工作群 |
| 负责人或管理员 | `驳回申请 12 原因` | 驳回并告知申请人原因，不创建任务 |

这里的 12 是**申请编号**，与批准后生成的正式任务编号不同。批准后继续使用原来的认领、更新进度、提交和成果审核流程。已处理的申请不能重复批准或撤回。

提交后会私聊提醒负责人和管理员。通知失败不撤销已保存的数据，可通过查询命令查看；群公告失败需管理员手动通知，不要重复批准。

首次启动自动备份数据库并新增申请表，保留旧成员、任务和完成记录。申请记录同时纳入 Excel/CSV 导出与数据库备份，审批操作纳入操作日志。


这一版基于你当前 v4 任务系统继续升级，并兼容旧数据库。**不要删除 `notes_department.db`。**

## v5 新增

### 1. 提交 → 审核 → 完成
成员不再直接把任务标成完成，而是：

```text
认领 → 提交成果说明/链接 → 待审核 → 管理员通过/打回 → 完成
```

成员命令：

```text
提交 12
完成 12          # 与“提交 12”等价，兼容旧习惯
撤回提交 12
```

发送 `提交 12` 后，Bot 会继续询问成果说明或链接。可以填写：

- GitHub / 网盘链接；
- 群文件名；
- 简单的成果存放位置说明。

管理员审核：

```text
待审核
通过 12 张三
打回 12 张三 第3页公式需要修订
```

多人任务中，每个参与成员分别审核；只有所需人数全部审核通过后，任务整体才变为“已完成”。

### 2. 管理员操作日志

```text
操作日志
操作日志 50
```

记录发布、修改、删除、恢复、重开、审核、管理员/成员调整等操作。

### 3. 统计

```text
本周统计
本月统计
成员统计 张三
```

包括新增任务、整体完成任务、认领份额、审核完成份额、参与人数、当前待审核和进行中任务。

### 4. 自动备份

Bot 启动后会自动创建当天数据库备份，之后每小时检查一次，但每天最多生成一份：

```text
backups/
  notes_department_2026-09-20.db
```

默认仅保留最近 30 份每日备份。

数据库升级到 v5 前还会自动创建一次：

```text
notes_department.backup_before_v5_时间.db
```

### 5. 数据导出

```text
导出数据
```

生成 Excel (`.xlsx`)，包含：成员、任务、认领与提交、管理员操作日志。

```text
导出CSV
```

生成一个 ZIP，里面是多个 UTF-8 BOM CSV 文件。

Bot 会尝试直接通过 NapCat 私聊发送文件；如果当前 NapCat 文件接口发送失败，文件仍会保存在本地 `exports/` 目录，并在私聊中告诉你路径。

### 6. 群公告

为了避免刷屏，只对较重要事件发群公告：

- 新任务发布；
- 任务人数已满；
- 任务信息被管理员修改；
- 任务整体审核完成；
- 任务重开 / 重新开放；
- 任务删除 / 恢复。

普通的提交、审核中的中间步骤仍然主要走私聊。

## 更新方法

1. `Ctrl+C` 停止当前 Bot。
2. 先手动再备份一次你当前的 `notes_department.db`（可选，但推荐）。
3. 用此包中的以下文件覆盖原项目：

```text
bot.py
db.py
requirements.txt
```

4. **保留原来的：**

```text
config.json
notes_department.db
```

5. 激活原虚拟环境后安装新增依赖：

```powershell
pip install -r requirements.txt
```

6. 启动：

```powershell
python bot.py
```

第一次启动会自动迁移旧数据库，旧成员、旧任务、旧认领和旧完成记录都会保留。

## 交互菜单与两步进度更新

私聊发送 `帮助` 后，可在 5 分钟内回复 1～7 选择：我的待办、我的任务、提交任务、更新进度、本人时长、本人资料、申请任务。选择提交或进度后，再输入任务编号并填写说明。文字指令继续可用，发送 `取消` 退出。菜单按部门和 QQ 隔离；正在填写内容时不会启用数字菜单，防止学号、人数被误识别。

`更新进度 12` 会先询问说明，也兼容 `更新进度 12 初稿完成`。保存前再次校验本人认领与任务状态。普通成员使用 `任务帮助`、`时长帮助`、`申请帮助`；`全部帮助` 仅对管理者开放。资料修改按部门与 QQ 定位，不改变任务和时长的身份关联。

## Windows 自动恢复与限制

按示例填写本机 config.json：`napcat_login_qq` 为机器人小号，`owner_qq` 为负责人。执行 `setup_napcat_credential.ps1`，交互输入密码，通过当前 Windows 用户的 DPAPI 保存本机凭据。执行 `install_napcat_restart_task.ps1` 并确认 UAC，安装 `NotesDepartmentNapCatRestart`。用户需已登录 Windows，任务不包含开机或登录触发器。

默认 NapCat 位于 `C:\NapCat.Shell`。watchdog 通过批处理触发任务：已有实例不重复启动，不主动杀掉 QQ；单次连接故障最多检查恢复 3 次，间隔递增。脚本检查 WebUI 登录账号和 OneBot 端口，状态保存在被 Git 忽略的 napcat_recovery_status.json。安全验证仍需本人扫码，不能绕过。WebUI Token 失效不等于 QQ 下线。

私聊和群消息检查发送返回值；失败会输出简要错误并抛出异常，不打印完整响应或凭据。QQ 内核 `1006514` 是发送异常线索，不能单独认定风控。WebSocket 在线、本地存在消息记录均不保证收件人收到。

本版未实现发送故障自动重启、通知持久化重试队列或月末定时导出。

### 邮件掉线告警（仅总负责人配置）

在运行目录建立本机专用 `email_alert.json`：

```json
{
  "enabled": true,
  "recipient": "owner@example.com",
  "smtp_source": "D:/path/to/pr-watcher/config.json"
}
```

发件服务复用所指定 JSON 中 `notify.mail` 的 `smtp`、`port`、`user`、`code`；不运行 pr-watcher，不复制授权码。端口 465 使用 TLS，其他端口要求 STARTTLS。路径必须指向已信任的本地配置。真实配置及告警状态不提交 Git。

总负责人私聊可发送 `配置邮箱 name@example.com`、`邮箱状态`、`测试邮件`。管理员和高级管理员不能修改 owner 的告警地址。邮箱指令只改收件人，不能通过 QQ 设置授权码。测试邮件一分钟最多一次。

Bot 每约 15 秒检查连接及 OneBot `get_status` 的 QQ 在线状态，连续异常 60 秒后告警；同一故障成功发信后不重复，发送失败最多三次、间隔至少五分钟。告警状态落盘以避免 Bot 重启重复发信，连续健康 120 秒后允许下一轮告警。异常时长从首次检查异常开始，SMTP 接受邮件不等于收件箱已送达。

此监测需要 Python Bot 和电脑网络仍在运行，无法检测自己的进程退出或在整机断网时发信；也不能证明 QQ 消息实际送达。不因邮件失败重启 NapCat。修改代码后需重启 Python Bot，邮箱配置在每次检查时读取。

离线验证：`python test_email_alert.py`（临时文件、模拟 SMTP，不发送邮件）。
